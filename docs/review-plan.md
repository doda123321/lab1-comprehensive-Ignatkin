# План code-review модуля src/discount.py

## 1. Цели ревью
- Точность расчетов: итоговая цена корзины считается корректно при любых сочетаниях скидок.
- Защита от фрода: нельзя получить цену ниже допустимого минимума или применить промокод повторно.
- Корректность применения скидок: порядок применения (базовая, промокоды, уровень лояльности) соответствует бизнес-правилам.

## 2. Измеримые критерии
- Отсутствие магических чисел: пороги и коэффициенты (15000, 0.85, 0.90, 0.97, 0.93, 0.70) вынесены в именованные константы.
- Валидация входных данных: cart_sum >= 0, tier из допустимого набора, promos - список строк.
- Покрытие тестами модуля > 80%.
- Линтер flake8 проходит без ошибок (зеленый статус в CI).
- Каждый комментарий ревьюера либо исправлен, либо закрыт обоснованием.

## 3. Участники и роли
| Участник | Роль | Ответственность |
|----------|------|-----------------|
| Игнаткин (doda123321) | Автор | Готовит код и тесты, отвечает на замечания |
| Ревьюер 1 | Разработчик | Проверяет логику расчетов и читаемость кода |
| Ревьюер 2 | QA-инженер | Проверяет покрытие тестами и граничные случаи |
| Tech Lead | Арбитр | Принимает решение в спорных случаях, финальный approve |

## 4. Процесс
1. Автор открывает Pull Request в develop и ждет зеленого статуса CI.
2. Ревьюеры оставляют комментарии в течение 2 рабочих дней.
3. Автор вносит правки отдельными коммитами.
4. Tech Lead делает финальный approve, после чего PR сливается.

## 5. Эскалация при спорах
1. Автор и ревьюер обсуждают спорный момент в комментариях к PR (не более 2 итераций).
2. Если согласия нет, к обсуждению подключается второй ревьюер.
3. Если спор остается, решение принимает Tech Lead, и оно является окончательным.
4. Принятое решение фиксируется комментарием в PR.
